# Chrome Web Store submission

Everything the listing needs, written out so submitting is copy-and-paste
rather than a writing exercise. Assets are generated by
`sh dev/shots/capture.sh` (start `npm run serve` first) into
`docs/screenshots/store/`.

Getting on the store is the single biggest thing standing between this and the
students who would use it: "turn on Developer mode and load unpacked" loses
most people before they reach step three.

## What only the account holder can do

1. Register at <https://chrome.google.com/webstore/devconsole> — a one-time
   $5 fee, paid once per Google account, not per extension.
2. Verify the publisher email on that account. An unverified publisher shows a
   warning on the listing.
3. Upload `dist/nst-attendance-<version>.zip` from `npm run package`.
4. Paste the fields below, attach the images, submit.

Review usually takes a few days. Each later version is a new zip upload against
the same listing, so the fields here only need writing once.

## Listing

**Name** (45 characters or fewer)

```
NST Attendance
```

**Short description** (132 characters or fewer, 125 used)

```
Combines lecture and lab attendance per subject on the Newton School portal, and tells you how many classes you can still skip.
```

**Category:** Education · **Language:** English

**Detailed description**

```
The Newton School portal lists a subject and its lab as two separate courses — "ADA - B" and "ADA Lab 2 - B". You can see each figure, but never the one that actually decides your eligibility: the combined attendance across both.

NST Attendance works it out and puts it on the course page, under "Your performance". Then it answers the question you actually have.

WHAT YOU GET

• One line per subject. "Can skip 6 more classes and stay above 75%", or "Attend the next 4 classes in a row to reach 75%". The percentage sits beside it as evidence, not as the point.
• Subjects that need attention are listed first, and the toolbar icon carries a badge when any subject is below your target.
• The exact classes you missed — dates, whether it was a lecture or a lab, and which were waived.
• A toolbar popup with the same numbers, so you can check without opening the portal. Alt+Shift+A opens it.
• Any target you like, not just 75%.

HOW MANY CAN I MISS FOR THE REST OF TERM

Tell it how long your term runs and how many classes a week a subject has, and the answer stops being about today: "Miss at most 5 of your 26 remaining classes." It warns you the moment the target stops being reachable, instead of letting you find out in week eleven.

Nothing is turned on for you. A projection built on a term nobody confirmed is exactly the number that would get someone to skip a class they could not afford, so the setup button states the figures it will use and the click is you confirming them.

HONEST ARITHMETIC

Attendance is rolled up by adding raw class counts, not by averaging percentages. Those two only agree when the theory and lab have held the same number of classes: 100% over 2 labs and 50% over 30 lectures averages to a comfortable-looking 75% when the real figure is 53%.

If it cannot read real numbers, it shows none. No estimates, no filled-in blanks, no confident wrong answers.

PRIVACY

No backend. No analytics. No third-party code of any kind, and no dependencies.

It reads your attendance through the portal's own API, using the session already in your browser, and it can reach no other site: the only host access it requests is my.newtonschool.co. Your settings and the cached numbers stay in your own browser profile.

The whole thing is open source under the MIT licence, so none of that has to be taken on trust:
https://github.com/yats0x7/nst-attendance

ON YOUR PHONE

No browser on Android or iOS runs extensions. There is a bookmarklet that gives you the same card on the portal page:
https://yats0x7.github.io/nst-attendance/

Not affiliated with or endorsed by Newton School. Built by a student who got tired of adding it up by hand.
```

## Privacy practices

**Privacy policy URL**

```
https://github.com/yats0x7/nst-attendance/blob/main/PRIVACY.md
```

**Single purpose**

```
Showing a student their own attendance on the Newton School portal, combined across each subject's lecture and lab components, together with how many classes they can miss while holding their required minimum.
```

**Justification — `storage`**

```
Stores the student's own settings (attendance target, term schedule, any manual subject grouping) and a short-lived cache of the attendance figures already fetched for the page. The cache exists to avoid re-requesting the same numbers while a student clicks between subject pages. Everything written stays in the browser profile; none of it is transmitted anywhere.
```

**Justification — host permission `https://my.newtonschool.co/*`**

```
This is the portal the extension exists to read. The content script runs only on this host, and the attendance figures come from this host's own API using the session the student is already logged into. No other host is requested, and no request is made to any other origin.
```

**Data collection disclosures**

Every category is answered *no*. Nothing is collected, nothing is transmitted,
and there is no server to send it to.

Tick all three certifications:

- Data is not sold to third parties.
- Data is not used or transferred for purposes unrelated to the single purpose.
- Data is not used or transferred to determine creditworthiness or for lending.

## Likely review questions

**"Why does it need host access?"** The answer is in the justification above:
the extension reads one site, and that site is the whole product. It is the
narrowest possible host pattern for what it does.

**"Remote code?"** None. No CDN, no `eval`, no dynamically fetched script.
Extension pages run under `script-src 'self'`. Everything executed is in the
package.

The phone bookmarklet does load a script from GitHub Pages, but it is not part
of this package and is not installed by it — it is a separate page a student
visits in their own browser.
